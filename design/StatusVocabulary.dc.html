The status vocabulary
Six states, shared by all three directions. Every one is computable from the database as it stands today — no schema change needed.
Awaiting first review
Assigned as a reviewer and has not opened it yet. Nobody has heard from them on this PR.
status = PENDING
no PR_APPROVED by this user
Awaiting re-review New
They approved once, then the author pushed again and Bitbucket reset them to pending. The board tells this apart from never having looked.
status = PENDING
PR_APPROVED by this user exists
PR_UPDATED came after it
Changes requested
The reviewer has done their part. The ball is with the author now, and the board says so rather than blaming the reviewer.
status = CHANGES_REQUESTED
Approved
Signed off and still valid — no push has landed since. Nothing is owed by this person.
status = APPROVED
Stale New
A modifier, not a state of its own — any waiting PR with no event at all for three days wears it. This is what a nudge should target.
newest PREvent older than 3d
threshold configurable
Ready to merge
Every assigned reviewer has approved and none of those approvals is stale. The only PR state that asks the author to act on good news.
prService.areAllReviewersApproved()
One PR, many reviewers — which state wins A PR shows a single headline state. The most urgent unresolved reviewer state takes it, so a PR never appears in two places at once.
